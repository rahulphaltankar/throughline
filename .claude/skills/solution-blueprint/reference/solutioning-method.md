# Solutioning Method

Use this as the detailed reasoning guide behind the master Skill.

1. Start from intent, not technology. Preserve source wording and establish problem, actor, impact, outcome and boundaries before proposing technology.
2. Classify the solution shape: software, data, AI/GenAI, agentic, automation, digital twin, computer vision, customer digital, workforce, supply chain, transformation, regulated, physical-world or hybrid.
3. Work dependency-first: problem → evidence → objectives → requirements → options → recommendation → architecture → data/integration/AI → trust → commercial → delivery/PMO → assurance → deployment → operations → value/lifecycle.
4. Make uncertainty explicit as evidence to research, assumption with validation, open question, or human decision.
5. Prefer reversible decisions and expose lock-in and decision debt.
6. Avoid architecture theatre: every major component should serve a requirement or operating need.
7. Derive PMO work from the chosen solution and dependencies.
8. Research to answer decision-relevant questions; record what evidence proves and does not prove.
9. Reconcile requirements, architecture, data flows, controls, delivery, resources, schedule and economics before finalising.
