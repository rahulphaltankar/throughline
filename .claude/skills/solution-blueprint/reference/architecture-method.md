# Architecture Method

Select only the views warranted by the problem: context/system landscape, capability/business, logical, application/component, data, integration/API/event, AI, security, physical/deployment.

Rules:
- Start from requirements and quality attributes.
- Separate logical design from product/vendor choices.
- Use generic labels unless named systems are known or verified.
- Show trust boundaries and ownership when relevant.
- Every material data flow has source, processing, destination/consumer, ownership and security implications.
- Keep diagrams and prose consistent.
- Explain alternatives and trade-offs.
- Identify assumptions and evidence that could change the design.

Prefer simple editable Mermaid diagrams.
